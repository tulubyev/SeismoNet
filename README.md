# 🌐 SeismoNet Иркутск

### Сеть сейсмических наблюдений за объектами гражданской и промышленной инфраструктуры г. Иркутска

---

## О проекте https://seismonet.ru

**SeismoNet** — профессиональная система мониторинга сейсмической безопасности строительных объектов Иркутска. Система предназначена для организаций, осуществляющих строительство и эксплуатацию гражданских и промышленных объектов в сейсмоопасном регионе.

Платформа объединяет:
- сеть датчиков (акселерометров) на объектах
- онлайн-концентратор сейсмических данных
- инструменты инженерного анализа (грунты, усиление, спектры)
- нормативную базу (СП, СНиП, ГОСТ)
- автоматические оповещения при сейсмических событиях

## Возможности

### 🏗 Объекты мониторинга
- Реестр инфраструктурных объектов с адресами, категориями и характеристиками
- Привязка застройщиков к объектам
- Геологические профили по каждому объекту (скважины, литология, категория грунта по СП 14.13330.2018)
- Интерактивная карта объектов (Leaflet)

### 📡 Датчики и станции
- Управление сетью сейсмических станций
- Мониторинг статуса (онлайн / деградация / отключена)
- Контроль заряда батарей, объёма памяти, качества данных
- Онлайн-концентратор: живые осциллограммы с каждого канала в реальном времени (WebSocket)

### 📊 Анализ данных
- **Сейсмограммы** — просмотр записей, каталог событий
- **Спектральный анализ** — Фурье-спектры, спектры отклика, ANSA
- **Инженерная геология** — база грунтовых профилей с параметрами Vs30, f₀, коэффициент усиления
- **История расчётов** — архив всех выполненных расчётов с заметками и версионированием

### 🔬 Расчёты и проектирование
- Метод тонких слоёв (МТСМ) — расчёт усиления грунта
- МКЭ (метод конечных элементов) — моделирование отклика конструкций
- Спектры ответа конструкций, спектры ANSA
- Генерация PDF-отчётов (с кириллицей)

### 📚 Нормативная база
- Актуальные нормы: СП 14.13330.2022, СНиП II-7-81*, ГОСТ 17516.1-90 и другие
- Карты ОСР-2015 (A, B, C)
- Таблицы сейсмических категорий грунтов

### 🔔 Оповещения
- Автоматические уведомления при превышении пороговых значений
- Интеграция: **Telegram**, **Email (Unisender)**, **Slack**
- Синхронизация с USGS и JMA (Японское метеорологическое агентство)

## Заказчики

Система мультитенантная: **заказчик** (customer) — организация-владелец объектов мониторинга (ЕЦСЭМ,
ГАУ РД «Сейсмобезопасность» и т. д.). Каждый объект, станция, застройщик, грунтовый профиль, расчёт,
датчик, сессия калибровки и набор сравнения принадлежат ровно одному заказчику; пользователь видит и
создаёт только строки своего заказчика. Создаются и редактируются заказчики в `/admin/customers`
(доступно только роли `superadmin`). Любой пользователь, кроме superadmin, обязан быть привязан к
заказчику — иначе все запросы к API отклоняются с ошибкой `no_customer`. Superadmin может переключаться
между заказчиками или работать в режиме «Все заказчики»: создание новых записей в этом режиме заблокировано
(`requireCustomer` требует ровно одного выбранного заказчика), но просмотр, редактирование и удаление
существующих строк любого заказчика остаются доступны — superadmin намеренно всемогущ.

## Быстрый старт (разработка)

### Требования
- Node.js 20+ (проверено на 24)
- SSH-доступ к VPS `90.156.168.149` (там живёт единственная БД проекта `seismonet_db`)

### Установка

```bash
git clone https://github.com/tulubyev/SeismoNet.git
cd SeismoNet
npm run setup          # npm install + .env из шаблона + SSH-туннель к БД
```

### Переменные окружения

`npm run setup` создаст `.env` из `.env.example`. Заполнить минимум:

```env
DATABASE_URL=postgres://tulubyev:<пароль>@localhost:5433/seismonet_db   # через туннель
SESSION_SECRET=<openssl rand -hex 32>
```

Опционально: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `UNISENDER_API_KEY`, `PORT`.

### База данных

Локального PostgreSQL нет. БД одна — на VPS, доступ с Mac через SSH-туннель:

```bash
npm run tunnel -- start     # localhost:5433 -> VPS:5432
npm run tunnel -- status
npm run tunnel -- stop
```

Схема уже развёрнута. `npm run db:push` меняет схему общей базы — запускать осознанно.
Для БД, созданных до миграции 0006 (роли): `npm run migrate:roles` один раз конвертирует старые роли
в шесть новых и перехэширует пароли, хранившиеся открытым текстом. Повторный запуск безопасен.
Кнопка «Войти как dev» на `/auth` и `POST /api/dev-login` существуют только при `NODE_ENV=development`.

### Запуск

```bash
npm run dev
```

Приложение: `http://localhost:5000` (порт — `PORT` в `.env`). Вход в dev — кнопка на `/auth`.

### Продакшн-сборка

```bash
npm run build
npm start
```
